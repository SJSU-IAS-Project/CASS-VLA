## 1. Mac setup working end to end

Iteration loop: edit + commit in the Linux VM, `git pull` on the Mac, run
`./scripts/setup.sh`, which now mirrors its output to a timestamped log in the
UTM shared folder (`/Users/user/vm/shared/claude-code` == `/mnt/utm-share` in
the VM) so the log can be read from the VM without copy-pasting.

Headless env and the top-down renderer passed on the first run. The Panda3D 3D
window failed with "Could not open window" and no reason, because MetaDrive
sets Panda3D's display logging to fatal. Diagnosed with `scripts/probe_window.py`
(bare Panda3D vs. MetaDrive settings, each stage in its own process):

1. MetaDrive 0.4.3 hardcodes `multisamples 8`. Apple's GL-on-Metal compat
   context has no 8x multisampled pixel format (`Could not find a usable pixel
   format`). 0x and 4x work.
2. One layer deeper it initialises simplepbr with `msaa_samples=16`, which
   fails the same way, so FilterManager returns None (`'NoneType' object has
   no attribute 'set_shader'`).
3. Its PBR shaders are GLSL 330 while the default Apple context is GL 2.1.

Upstream fixed all three for macOS in PR #794 (2025-01-09, 12 files: GL 4.1
core context, 4x MSAA, GLSL 330 shaders), a month after the 0.4.3 release;
nothing newer is on PyPI. So `requirements.txt` now pins MetaDrive to git
commit `85e5dadc` (main, 2025-05-12). It still reports VERSION 0.4.3 and
downloads the same assets; the only cross-platform change is panda3d 1.10.16.

Final Mac run (`--force --gui --probe --window`): all four setup checks pass,
3D window renders 120 steps, bit-identical replay over 38 steps.
`docs/phase1_findings.md` records this plus the probe answers (Q1–Q4).

Also: `check_setup.py` runs the 3D-window check in a subprocess so a failure
can no longer cascade into "Attempt to spawn multiple ShowBase instances!".

## 2. Phase 1 scenario scripting (`cassvla/scenarios/`)

The capability probe showed PG maps have no traffic lights and no light
manager (MetaDrive only has one for replayed real-world data). Built:

- **`SignalManager`** — spawns a `BaseTrafficLight` on every lane leaving every
  approach of the first X/T block (36 on X), groups approaches into ego/cross
  by heading, drives phases from a fixed cycle or a scripted per-seed
  schedule. `env.signals.get_state()` returns per-lane status, ego/cross phase
  and stop points. The ego's `red_light` flag and IDM traffic respond.
- **`HazardManager`** + hazard types — `ParkedVehicle`, `Barrier`,
  `CrossingPedestrian` (trigger on ego distance), `KinematicVehicle`
  (event-driven speed/lane changes: `t`, `ego_within`, `ego_near`,
  `eta_match`), `IDMVehicle`. `env.hazards.get_state()` logs positions,
  speeds and triggers fired.
- **Six families** (`families.py`), per refined proposal §4:
  `occluded_pedestrian`, `occluded_cross_traffic`, `ambiguous_light`,
  `lead_brake_cutin`, `lane_blockage`, `merge_closing_speed`. The two
  intersection families run on map `X` with signals.
- **`HazardEnv` / `make_env(family, seed)`** registers both managers.
- `scripts/run_scenarios.py` (summary table, `--frames` saves top-down PNGs to
  `out/scenarios/`), `tests/test_scenarios.py` (7 checks incl. bit-identical
  replay; all pass), `docs/scenarios.md`.

Red-light-runner timing: a fixed distance trigger missed the ego by ~2.4 s.
Replaced with an ETA-matching trigger that uses the ego's measured
acceleration and a 0.5 s launch lag; with a random lead of ±1.2 s, 4/8 seeds
collide and the rest are 3–11 m near misses, identical at throttle 0.5 and
0.25 (i.e. independent of the ego policy).

MetaDrive quirks hit: managers get a legacy `RandomState` (`randint`, not
`integers`); vehicles spawned on negative-direction roads need an explicit
`destination` or route assignment crashes; velocity commands on Bullet
vehicles take ~0.5 s to take effect.
