The PlanDiscrim idea is interesting, but the current project scope is too large for one semester. You are simultaneously proposing a candidate planner, VLA safety critic, multiple perception tools, active tool selection, conformal risk calibration, replanning/fallback logic, and closed-loop evaluation. I recommend making planner-discriminative tool selection the core project: given a small set of candidate trajectories and an ambiguous scene, determine which single additional perception query is most useful for deciding between those candidates. Start with only 2–3 tools, such as object/ROI inspection, depth/distance estimation, and geometric collision checking, and use MetaDrive simulator state to generate oracle labels for which tool would actually change the correct candidate ranking. Compare no tool, random tool, generic uncertainty-based selection, always-on tools, and PlanDiscrim. The VLA can initially be used offline or with cached outputs rather than being required at every simulation step. Only after this evaluation works should you add conformal calibration, repeated tool calls, or a full ACCEPT/INSPECT/REPLAN/FALLBACK supervisor. A strong result would show that trajectory-conditioned tool selection achieves similar or better safety decisions with substantially fewer perception/VLA calls than generic or always-on verification.
