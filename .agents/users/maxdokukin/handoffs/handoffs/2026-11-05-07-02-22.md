## 6. Design decisions

- **Decision:** Commit the window code now, and treat its values as provisional.
  **Why:** The human asked for a commit before the move. The plumbing is sound, but the `t_window` values came from sweeps on buggy hazards, so step 2 of the plan replaces them.
  **Alternatives rejected:** Holding the commit until the sign fix, which was the earlier recommendation.

- **Decision:** The human runs the commits, with no push and no AI attribution, on the instruction "lets 1. commit to git".
  **Why:** The harness guardrail blocked `git commit` from the agent, and the human did not ask for a push. R-10 forbids attribution trailers.
  **Alternatives rejected:** Working around the guardrail.

- **Decision:** Choose windows by rule: the smallest contiguous range of the 0.5 s grid that holds at least 95% of a family's retained decisions on the tuning seeds. Do not change a window after seeing validation results.
  **Why:** Hand-picked windows would inflate retained rates.
  **Alternatives rejected:** A per-family `cruise` override, which was not needed.

- **Decision:** Seeds 10-19 count as seen. Validate new windows on seeds 20-29, and start dataset seeds at 100.
  **Why:** This keeps tuning seeds out of the dataset and its test split.
  **Alternatives rejected:** Reusing seeds 10-19 for validation.

- **Decision:** Leave the 0.8 speed problem undiagnosed for now, and log measured actor velocity in the records.
  **Why:** The cause is unknown, and the tools need true velocity whichever way that turns out.
  **Alternatives rejected:** Fixing it together with the sign bug.

- **Decision:** Do not give an overnight run the HPC login, and did not bypass the ssh host key check for `research`.
  **Why:** Both are the human's to control.
  **Alternatives rejected:** `StrictHostKeyChecking=accept-new`.
